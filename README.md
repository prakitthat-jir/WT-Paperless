# WT Paperless

ระบบตรวจสอบแบบไร้กระดาษของ **แผนกคลังสินค้าและจัดส่ง — INTER GROUP PACKAGING**
แทนที่ AppSheet ด้วยเว็บแอปหน้าเดียวที่บันทึกลงไฟล์ Excel บนเครื่องในออฟฟิศโดยตรง

| แบบฟอร์ม | รหัส |
|---|---|
| การตรวจสอบรถขนส่ง ก่อน-หลัง ขึ้นสินค้า | FM-PB-007 Rev.03 |
| การตรวจสุขลักษณะส่วนบุคคล | FM-CG-029 Rev.00 |
| การสำรวจวัสดุที่ทำด้วยแก้วและวัสดุที่แตกหักได้ | FM-CG-027 Rev.01 |
| ใบตรวจสอบสภาพรถขนส่ง | FM-TB-012 Rev.00 |
| แบบประเมินผู้รับเหมาในการบริการขนส่ง | FM-QMR-021 Rev.01 |

## ⚠️ repo นี้ไม่มีข้อมูลจริง

**ห้าม commit ข้อมูลบริษัทลง repo นี้** — ทั้งประวัติการตรวจ รายชื่อผู้รับเหมา
เบอร์โทรพนักงาน ที่อยู่ หรือรูปลายเซ็น เพราะ GitHub Pages เป็นเว็บสาธารณะเสมอ
แม้ repo จะตั้งเป็น private ก็ตาม

ข้อมูลทั้งหมดอยู่บนเครื่องแม่ในไฟล์ที่ `.gitignore` กันไว้แล้ว:

```
WT-Paperless-Base.json     ข้อมูลหลัก + ประวัติย้อนหลัง 40,636 รายการ
WT-Paperless-Data.json     รายการที่บันทึกใหม่ (ตัวจริง)
WT-Paperless-Data.xlsx     ไฟล์ Excel ที่ระบบเขียนให้อัตโนมัติ
WT-Paperless-Config.json   รหัสเข้าใช้งาน
WT-Paperless-Images/       รูปลายเซ็น
```

`tools/build.js` มีตัวตรวจข้อมูลส่วนบุคคลในตัว และจะ **ยกเลิกการ build**
ถ้าเจอชื่อ / ที่อยู่ / เบอร์โทร / อีเมล / ทะเบียนรถ หลุดเข้ามาในไฟล์ที่จะขึ้น GitHub

## โครงสร้าง

```
มือถือ / แท็บเล็ต (ที่ไหนก็ได้)
   │
   │  ①  โหลดหน้าจอ           https://<user>.github.io/wt-paperless/
   │  ②  ใส่รหัสเข้าใช้งาน
   │  ③  อ่าน/เขียนข้อมูล      https://xxxx.trycloudflare.com/api/…
   ▼
เครื่องแม่ที่ออฟฟิศ (Node.js)  ──►  WT-Paperless-Data.xlsx
```

- **หน้าจอ** เป็นไฟล์นิ่ง ๆ ไม่มีข้อมูล วางบน GitHub Pages ได้อย่างปลอดภัย
- **ข้อมูล** ไม่เคยออกจากเครื่องแม่ ไม่มี cloud database
- **อุโมงค์** (Cloudflare Tunnel) ทำให้เข้าถึงเครื่องแม่ได้โดยไม่ต้องเปิดพอร์ตที่เราเตอร์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | ตัวแอปทั้งหมด — หน้าจอ, ฟอร์ม, การพิมพ์ A4, PWA |
| `WT-Paperless.webmanifest`, `WT-Paperless-SW.js`, `WT-Paperless-Icons/` | ทำให้ติดตั้งลงหน้าจอโฮมได้ |
| `server/WT-Paperless-Server.js` | เซิร์ฟเวอร์บนเครื่องแม่ — เขียน .xlsx เอง ไม่มี dependency |
| `server/START-WT-Paperless.bat` | ปุ่มเปิดระบบ |
| `tools/build.js` | คัดไฟล์โค้ดจากโฟลเดอร์ออฟฟิศมาลง repo + ตรวจข้อมูลรั่ว |

## ติดตั้งบนเครื่องแม่ (ทำครั้งเดียว)

1. ติดตั้ง [Node.js LTS](https://nodejs.org)
2. คัดลอกไฟล์ในโฟลเดอร์ `server/` ไปไว้ในโฟลเดอร์ข้อมูลของบริษัท
   (โฟลเดอร์เดียวกับ `WT-Paperless-Data.xlsx`)
3. คัดลอก `index.html` ไปไว้ในโฟลเดอร์เดียวกันโดยเปลี่ยนชื่อเป็น `WT-Paperless-WebApp.html`
   พร้อมกับ `WT-Paperless.webmanifest`, `WT-Paperless-SW.js`, `WT-Paperless-Icons/`
4. ดับเบิลคลิก `START-WT-Paperless.bat`

เปิดครั้งแรกระบบจะสร้าง `WT-Paperless-Config.json` พร้อมรหัสเข้าใช้งาน 6 หลักให้เอง
(แก้เป็นรหัสที่จำง่ายกว่าได้ในไฟล์นั้น แล้วเปิดโปรแกรมใหม่)

### ให้เข้าถึงจากนอกออฟฟิศ

ดาวน์โหลด `cloudflared.exe` จาก
<https://github.com/cloudflare/cloudflared/releases> (เลือก `cloudflared-windows-amd64.exe`)
แล้ววางไว้ข้าง `WT-Paperless-Server.js` — ระบบจะเปิดอุโมงค์ให้อัตโนมัติตอนเริ่มทำงาน
และแสดงลิงก์สำหรับพนักงานในหน้าต่างสีดำ

> ที่อยู่อุโมงค์แบบไม่ใช้โดเมนจะ **เปลี่ยนใหม่ทุกครั้งที่เปิดโปรแกรม**
> ให้เปิดเมนู “ติดตั้งเป็นแอป” ในแอปแล้วให้พนักงานสแกน QR ใหม่
> ถ้าอยากได้ที่อยู่คงที่ ต้องใช้ Cloudflare Tunnel แบบผูกโดเมน

## เผยแพร่หน้าเว็บ (GitHub Pages)

1. push repo นี้ขึ้น GitHub
2. **Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)`**
3. รอสักครู่จะได้ที่อยู่ `https://<user>.github.io/wt-paperless/`
4. เอาที่อยู่นั้นไปใส่ในแอปที่เครื่องแม่: **ตั้งค่า → ที่อยู่หน้าเว็บที่เผยแพร่**
   ระบบจะสร้างลิงก์ + QR ที่รวมที่อยู่อุโมงค์ให้พนักงานอัตโนมัติ

อัปเดตหน้าเว็บครั้งถัดไป:

```bash
node tools/build.js && git add -A && git commit -m "update app" && git push
```

## ความปลอดภัย

- ทุกคำขอที่มาจากอุโมงค์ต้องมีโทเคน ซึ่งได้จากการใส่รหัสเข้าใช้งาน
  (โทเคนเซ็นด้วย HMAC-SHA256 อายุ 30 วัน)
- ใส่รหัสผิดเกิน 5 ครั้ง ถูกล็อก 5 นาทีต่อ IP
- เข้าจากในออฟฟิศ (localhost / วง LAN) ไม่ต้องใส่รหัส
  เปลี่ยนได้ด้วย `"requireCodeOnLan": true` ใน `WT-Paperless-Config.json`
- `WT-Paperless-Base.json` และ `WT-Paperless-Config.json` เรียกตรง ๆ ทาง HTTP ไม่ได้ (403)
- นี่คือรหัสรวมชุดเดียวทั้งแผนก — **ไม่ได้แยกสิทธิ์รายคน และไม่มี log ว่าใครเข้ามาเมื่อไหร่**
  ถ้าต้องการระดับนั้นต้องทำระบบผู้ใช้เพิ่ม
